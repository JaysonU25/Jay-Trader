# Jay Trader cron

Cloudflare Worker that fires the seven ingest jobs on schedule. It holds no
business logic: it signs a request and posts it to the API's
`/internal/ingest/{job}`, which answers `202` and runs the job in the
background.

## Deploy

```bash
npm install
npx wrangler secret put INGEST_HMAC_SECRET   # must equal the API's value
npx wrangler deploy
```

`API_BASE_URL` lives in `wrangler.toml` under `[vars]` — it is only an origin,
so it is not a secret. Update it when the API's hostname changes.

## Verify

```bash
npx wrangler tail                                  # watch live invocations
npx wrangler dev --test-scheduled                  # then, in another shell:
curl "http://localhost:8787/__scheduled?cron=15+13+*+*+*"
```

A successful fire logs `triggered macro`. A `401` means the Worker's
`INGEST_HMAC_SECRET` does not match the API's — the error message carries the
response body precisely so that is not mistaken for a bad URL.

## Schedule

| Cron (UTC) | Job | Why then |
|---|---|---|
| `15 13 * * *` | `macro` | after the 08:30 ET FRED releases |
| `30 15 * * 1-5` | `fx` | after the ECB publishes, ~15:00 UTC |
| `0 22 * * 1-5` | `prices` | after the US close, 21:00 UTC |
| `0 */6 * * *` | `crypto` | four times daily |
| `10 */6 * * *` | `news` | offset from crypto, see below |
| `0 23 * * *` | `earnings` | |
| `0 4 * * 1` | `ratings` | weekly; analyst ratings barely move |

**Every expression must be unique.** Cloudflare passes the matched expression as
`event.cron`, and that string is the only thing distinguishing one trigger from
another. Spec 5.2 assigns `crypto` and `news` the same `0 */6 * * *`, which
would leave one of them unroutable, so `news` is offset by ten minutes. Two
tests guard this: one asserts the expressions are distinct, one asserts the
mapped job names match `JOB_NAMES` in `marketpulse/ingest/jobs.py` exactly.

## Signing

`HMAC-SHA256` over `` `${timestamp}.${job}` ``, hex encoded, sent as
`X-Signature` beside `X-Timestamp`. The API rejects anything older than 300
seconds, so the two clocks need only agree within that window.

`tests/sign.test.ts` pins a vector generated by the Python implementation the
API verifies with. If the two ever drift, that test fails rather than every
scheduled trigger quietly 401-ing in production.
